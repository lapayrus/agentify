# 02: The daemon is windowless and belongs to the app

**Category:** bug
**Status:** ready-for-agent
**Blocked by:** none (ADR-0006 decides the lifetime)
**Blocks:** 04

**What to build:** No console window, ever. The shell starts the daemon on demand and stops it when the last
Agentify process exits; the MCP shim guarantees a daemon for its own session. Nothing from Agentify is resident
while the app is closed, and closing the app leaves no daemon, no Caddy, and no shim behind.

## Evidence

- `crates/daemon/src/main.rs` has no `windows_subsystem`, so release `agentifyd.exe` is a console app; the
  `Agentify Daemon` task runs it with `InteractiveToken` at logon, which is the terminal window.
- `ui/src-tauri/src/main.rs` already carries `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`;
  `crates/backends/src/wsl/cli.rs` and `crates/ingress/src/caddy.rs` already use `CREATE_NO_WINDOW`.
- The daemon writes no log file (the data root's `logs\` is empty), so a windowless release build would have no
  diagnostics without adding one.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** bug
**Summary:** The release daemon is windowless, owned by the shell's job object, and gone when the app exits; an MCP-only daemon idles out once its work is done.

**Settled decisions:**
- The shell adopts a live matching daemon rather than spawning a second one, and owns it until exit.
- A daemon with no owner exits after ten idle minutes; it never idles out while an Environment is running or an
  Operation is in flight.
- There are two owner kinds only: the shell, or an MCP shim session. There is no machine-level owner.

**Current behavior:**
The release daemon is a console program launched by a logon task with an interactive token, so a terminal window
appears and survives the app. The shell spawns the daemon detached and drops the handle; nothing stops it, its
Caddy child, or a shim when the app closes.

**Desired behavior:**
A release daemon runs with no console and is started as a child of its owner. The shell places it in a Windows
Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, so quitting stops the daemon and its Caddy child, and a
shell crash does too. Adopting a live daemon transfers ownership: the shell stops it on exit. The shim reuses a
live daemon, starts one when none answers, and retries once by starting a new one if its daemon disappears. A
daemon with no owner exits after ten idle minutes only when every Environment is stopped and no Operation is in
flight. The daemon writes a bounded log under the data root. The installer stops registering the logon task, and
any upgrade removes a task left by v0.1.2.

**Key interfaces:**
- Daemon binary subsystem: GUI in release, console in debug.
- Windows process-creation flags on every spawn of the daemon and its children.
- A job object held by the shell for the daemon's process, and by the shim for its own session.
- An owner signal from the spawning process that disables idle exit.
- The shim's daemon-resolution path: reuse, spawn, retry.
- A bounded daemon log file under the data root.
- Installer hooks: stop registering the logon item.

**Acceptance criteria:**
- [ ] No console window appears for a release build at logon-start, shell launch, or MCP session start.
- [ ] Quitting the shell leaves no daemon, no Caddy, and no shim process.
- [ ] Killing the shell process also ends the daemon and Caddy.
- [ ] With the app closed, an MCP call starts a daemon and succeeds; that daemon exits after the idle window when no Environment is running.
- [ ] A daemon with a running Environment never idle-exits.
- [ ] Opening the shell while a shim-started daemon is live adopts it — one daemon, same port — and stops it on exit.
- [ ] Upgrading from v0.1.2 removes the old logon task.
- [ ] An exit leaves a bounded log explaining why, with no console.
- [ ] The operator documentation no longer promises a daemon that outlives the UI.

**Out of scope:**
- Stray-daemon reconciliation rules (01).
- A tray icon, menu, or "keep running in background" option.
- Caddy's lifecycle beyond dying with the daemon.
